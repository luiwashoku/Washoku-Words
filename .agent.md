# Washoku Study Companion

## Project Overview

This project converts a personal Washoku notebook into a high-quality study application.

The goal is **not** to make a vocabulary quiz.

The goal is to create an interactive learning companion that teaches Japanese culinary language the same way a Japanese chef or Washoku teacher would naturally use it.

The application should prepare the learner to:
- understand Washoku classes taught entirely in Japanese
- communicate with chefs and fermentation teachers
- distinguish subtle vocabulary and nuance
- think directly in Japanese rather than translating
- build long-term recall instead of short-term recognition

Every notebook page becomes one JSON deck.

## Project Structure and Running Locally

This is a dependency-free static web application:
- `index.html` contains the application markup
- `styles.css` contains the visual styles
- `app.js` contains application behavior
- `data/catalog.json` lists the available lessons
- `data/pagesXX.json` contains lesson questions
- `nopush/和食探究ノート.pdf` is source material and must not be modified

Because the application loads JSON with `fetch()`, do not open `index.html`
directly from the filesystem. From the repository root, run:

```sh
python3 -m http.server 8000
```

Then open `http://localhost:8000`.

Keep the project dependency-free unless a task explicitly requires adding a
tool or framework. Preserve the existing plain HTML, CSS, and JavaScript style.

## JSON Requirements

Each page produces a single `pagesXX.json`.

Deck files contain a top-level JSON array. Use two-digit, zero-padded page
numbers in filenames, such as `pages01.json` and `pages52.json`.

Each question contains:
- id
- chapter
- page
- type
- difficulty
- question
- answers
- correct
- jpExplanation
- enExplanation

Always produce valid JSON.

Use these field conventions:
- `id`: unique within the project, formatted as `pageXX-qYY`
- `chapter`: non-empty Japanese chapter or lesson title
- `page`: integer matching the page number printed in the lower corner of the
  notebook page, not the PDF viewer's file-page index. When the user gives a
  page number, interpret it as this printed number.
- `type`: one of `recognition`, `application`, `dialogue`, `comparison`,
  `contrast`, `production`, `sequence`, or `scenario`
- `difficulty`: integer from 1 to 4, where 1 is introductory, 2 is easy,
  3 is intermediate/application, and 4 is nuanced or productive
- `question`: non-empty string
- `answers`: exactly four non-empty, distinct strings
- `correct`: zero-based index into `answers`, from 0 through 3
- `jpExplanation`: non-empty, natural Japanese explanation
- `enExplanation`: non-empty English explanation of meaning or nuance

Do not copy malformed legacy formatting into new decks. When editing an older
deck, bring the touched questions into compliance with these requirements.

### Catalog Updates

Whenever a deck is added, removed, renamed, or its size changes, update
`data/catalog.json`. Each catalog entry contains:
- `id`: `pageXX`
- `category`: one of `basics`, `food-culture`, `fermentation`, `techniques`,
  `conversation`, or `evaluation`
- `page`: the same page integer used by the deck
- `title`: the lesson title
- `file`: the repository-relative deck path
- `questionCount`: the exact number of questions in the deck

Keep catalog entries ordered by page number within their category.

## Furigana Rules

Use parentheses only.

Correct:
- 先生(せんせい)
- 火(ひ)
- 火入れ(ひいれ)
- 調味料(ちょうみりょう)

Never use:
- `{reading}`
- <ruby>
- <rt>

Whenever an edited deck contains legacy curly-brace furigana such as
`先生{せんせい}`, replace it with parenthetical furigana: `先生(せんせい)`.
This applies to questions, answer choices, and both explanation fields. Curly
braces used by JSON objects are structural syntax and must not be changed.

Only add furigana where it improves readability.

Apply the same furigana syntax to questions, answers, and explanations. Add
furigana to learner-facing kanji that is uncommon or important to the lesson;
it is not necessary for very basic kanji. Within one string, annotate a word
on its first occurrence unless repeating the reading prevents ambiguity.

## Question Philosophy

Never create dictionary quizzes.

Avoid:
- What does ○○ mean?
- Which translation is correct?

Contextual meaning checks are allowed when the Japanese appears in a realistic
teacher, chef, or cooking situation and the answer tests its meaning in that
specific context. A bare word-to-translation prompt is not allowed.

Instead teach through context.

### Real cooking situations

Start from food or cooking.

Example:
'You gently simmer daikon in seasoned broth. Which verb fits best?'

### Teacher dialogue

Frequently use:

先生(せんせい)：

These should resemble a real Washoku lesson.

### Compare similar words

Examples:
- さくさく vs ぱりぱり
- とろとろ vs とろける
- 煮る vs 煮込む

### Food-first thinking

Use realistic ingredients:
- tempura
- natto
- soba
- tofu
- shrimp
- lettuce
- miso
- sesame
- rice
- chawanmushi

Think:
Food → Japanese word

not

English → translation

### Scenario questions

Ask:
- Which expression sounds most natural?
- Which word would a chef use?
- Which description fits best?

### Sequence questions

Teach workflow.

### Production questions

Sometimes ask:
'What would you answer?'

## Answer Choices

Wrong answers should be believable.

Use vocabulary from the same topic.

Never use joke answers or obviously impossible distractors.

---

## Correct Answer Distribution

Randomize answer positions.

Do not put every correct answer as A.

Aim for an even distribution.

---

## Explanations

Every question includes:

### Japanese

Simple natural Japanese.
Explain nuance.

### English

Explain the concept.
Do not merely translate.

## Difficulty

Within each page:
- difficulty 1: introductory support or highly familiar context
- difficulty 2: easy recognition in a cooking context
- difficulty 3: application, dialogue, or comparison
- difficulty 4: nuanced distinctions, sequence, or production

Use a meaningful progression rather than placing all difficult questions at
the end. A deck should include difficulty 2 through 4; use difficulty 1 only
when the source material benefits from an introductory question.

---

## Mix Question Types

Use a combination of:
- recognition
- application
- dialogue
- comparison
- contrast
- production
- sequence

---

## Quality Standard

Page 3 is the benchmark.

Every new page should meet or exceed that quality.

Always ask:

'Will this help the learner actually understand and speak Washoku Japanese?'

If not, redesign the question.

---

## Language Policy

The learner is progressing toward Japanese-only instruction. Use English to
establish an unfamiliar cooking situation when needed, but increase the amount
of natural Japanese in dialogue, application, and production questions.
Japanese must sound like language used in a real cooking lesson, not a literal
translation from English.

Do not invent facts that are not supported by the notebook or reliable culinary
usage. Preserve distinctions and uncertainty when the source is ambiguous.

---

## Deck Size and Answer Distribution

Follow the requested question count when a task specifies one. Otherwise use
20 questions for a new page, expanding only when the source page contains
enough distinct material to avoid repetition.

Across a complete deck, distribute correct answer indexes as evenly as
possible. For a 20-question deck, each index should normally occur five times.
Do not create unnatural answer ordering merely to satisfy the distribution.

## Definition of Done

Before considering a content change complete:
1. Confirm every edited JSON file parses successfully.
2. Confirm all required fields and allowed values follow this document.
3. Confirm every `correct` index points to the intended answer.
4. Confirm IDs are unique and `questionCount` matches the deck length.
5. Check furigana uses parentheses and contains no `{}`, `<ruby>`, or `<rt>`.
6. Check correct-answer positions are reasonably balanced.
7. Serve the app locally and confirm the catalog and edited lesson load without
   console errors when browser testing is available.
8. Review distractors, both explanations, and Japanese phrasing for learning
   value rather than mere translation recall.

There is currently no automated test, lint, or formatting command. Use focused
syntax checks and manual browser verification. Do not claim browser verification
was performed if the environment did not allow it.

---

## Change Scope

Keep changes focused on the requested task. Do not modify the source PDF. Do
not rewrite unrelated decks solely to make them conform to newer conventions;
report legacy inconsistencies separately unless the user asks for a migration.
